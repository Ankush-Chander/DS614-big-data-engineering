Multi-Node Hadoop Cluster Lab (VirtualBox)

Goal: Simulate a real-world cluster environment using Virtual machines. Architecture: 1 Master Node (NameNode + ResourceManager) + 2 Worker Nodes (DataNode + NodeManager).

Prerequisites

  • Host Machine: At least 16GB RAM recommended (4GB per VM + Host overhead).
  • Software: VirtualBox, Ubuntu Server ISO (20.04 or 22.04 LTS).

Phase 1: Base VM Preparation

We create one perfect VM and clone it to save time.

  1. Create VM:
  2. Name: hadoop-base
  3. RAM: 4GB, Disk: 20GB (Dynamically allocated).
  4. Network: Bridged Adapter (important for unique IPs on LAN) or NAT Network.
  5. OS Install:
  6. Install Ubuntu Server.
  7. Create user hadoop.
  8. Software Install: 
    sudo apt update && sudo apt install -y openjdk-8-jdk ssh pdsh
wget [apache-hadoop-url].tar.gz
tar -xzvf hadoop-*.tar.gz
mv hadoop-* ~/hadoop
  9. Environment Variables (.bashrc):
  10. Set JAVA_HOME, HADOOP_HOME, and add bins to PATH.

Phase 2: Cloning & Networking

  1. Clone VMs:
  2. Shutdown hadoop-base.
  3. Clone to hadoop-master (Mac address policy: Generate new Mac addresses).
  4. Clone to hadoop-slave1.
  5. Clone to hadoop-slave2.
  6. Hostname & IP Setup:
  7. Boot each VM.
  8. Set hostname: sudo hostnamectl set-hostname master (do same for slave1, slave2).
  9. Check IP: ip addr show (Assumed: Master=192.168.1.10, Slave1=192.168.1.11, Slave2=192.168.1.12).
  10. Hosts File (/etc/hosts):
  11. On ALL nodes, edit /etc/hosts to include: 
    192.168.1.10 master
192.168.1.11 slave1
192.168.1.12 slave2
  12. SSH Key Exchange:
  13. On master: ssh-keygen -t rsa
  14. Copy id to all nodes (including itself): 
    ssh-copy-id master
ssh-copy-id slave1
ssh-copy-id slave2
  15. Verify: ssh slave1 should not ask for a password.

Phase 3: Hadoop Configuration (On Master)

Edit files in $HADOOP_HOME/etc/hadoop/

  1. core-site.xml: 
    <property>
  <name>fs.defaultFS</name>
  <value>hdfs://master:9000</value>
</property>
  2. hdfs-site.xml: 
    <property>
  <name>dfs.replication</name>
  <value>2</value> <!-- Since we have 2 slaves -->
</property>
<property>
  <name>dfs.namenode.name.dir</name>
  <value>/home/hadoop/hadoop_data/namenode</value>
</property>
<property>
  <name>dfs.datanode.data.dir</name>
  <value>/home/hadoop/hadoop_data/datanode</value>
</property>
  3. mapred-site.xml: 
    <property>
  <name>mapreduce.framework.name</name>
  <value>yarn</value>
</property>
  4. yarn-site.xml: 
    <property>
  <name>yarn.nodemanager.aux-services</name>
  <value>mapreduce_shuffle</value>
</property>
<property>
  <name>yarn.resourcemanager.hostname</name>
  <value>master</value>
</property>
  5. workers file:
  6. Replace localhost with: 
    slave1
slave2

Phase 4: Sync & Launch

  1. Copy Configs to Slaves: 
    scp $HADOOP_HOME/etc/hadoop/* slave1:$HADOOP_HOME/etc/hadoop/
scp $HADOOP_HOME/etc/hadoop/* slave2:$HADOOP_HOME/etc/hadoop/
  2. Format NameNode (Only on Master, Only ONCE): hdfs namenode -format
  3. Start Cluster (On Master): start-dfs.sh start-yarn.sh
  4. Verify Process:
  5. On Master: jps should show NameNode, ResourceManager, SecondaryNameNode.
  6. On Slaves: jps should show DataNode, NodeManager.

Phase 5: Verification Task

Run the WordCount example from the single-node lab, but observe the ResourceManager UI (http://master:8088) to see containers running on slave1 and slave2.
